# Codexを任意で使う場合のガイド

Codexは、コードの説明、変更案の作成、コマンド実行などを手伝うAIエージェントです。

**このプロジェクトでCodexは必須ではありません。** [`ONBOARDING.md`](../ONBOARDING.md) の手順は、VS Code・Git・ブラウザだけで完了します。Codexを使わない人も、同じようにPRを出せます。

このガイドは、Codexを自分の判断で補助ツールとして使う人だけが読んでください。サービスの画面や利用条件は変わるため、操作が違う場合は [OpenAIのCodex公式ドキュメント](https://learn.chatgpt.com/docs/codex/cli) を優先します。

---

## 1. Codexに任せてよいこと・いけないこと

初心者には、まず**コードを書かせるより、コードを説明させる**使い方を勧めます。

```text
app/faq/FAQClient.tsx の faqs 配列が何を表しているか、
Web開発が初めての人向けに説明して。ファイルは変更しないで。
```

Codexは便利ですが、次のことは保証しません。

- 出力したコードが正しいこと
- OIFの対外方針やDiscord・Notion内の決定を知っていること
- 変更がスマホでも正しく見えること
- あなたの代わりにPRの責任を持つこと

**理解できない変更はコミットしないでください。** AIが作った差分でも、PRを出した人が内容を説明できる必要があります。

## 2. アカウントと利用条件

Codexを使う人は、**各自のChatGPTアカウント**でサインインしてください。OIFの共有アカウントは使いません。

CodexはChatGPTのFreeを含む複数のプランで提供されていますが、利用上限や使える機能はプランによって異なり、今後変わることがあります。無料枠を使い切っても、OIFの開発に参加できなくなるわけではありません。Codexを閉じて、[`ONBOARDING.md`](../ONBOARDING.md) の人力手順を続けてください。

このリポジトリの作業のために、APIキーを発行したり料金を支払ったりする必要はありません。個人でAPIキー認証を使う場合、その利用料は本人のOpenAI Platformアカウントに発生します。

- [OpenAIの料金・プラン案内](https://learn.chatgpt.com/docs/pricing)
- [OpenAIの認証方法](https://learn.chatgpt.com/docs/auth)

## 3. セットアップ

### ターミナル版を使う場合

このリポジトリではNode.jsをすでに使うため、npmで導入できます。

```bash
npm install -g @openai/codex
codex --version
codex login
```

`codex login` を実行するとブラウザが開きます。「Sign in with ChatGPT」を選び、自分のChatGPTアカウントでサインインします。

`codex: command not found` になる場合は、まずターミナルを閉じて開き直します。それでも直らなければ、エラーメッセージと `npm -v` の結果をDiscordで共有してください。インストール方法は変更されることがあるため、無理にPATH設定を変更する前に公式手順を確認します。

### VS Code拡張を使う場合

VS Codeの拡張機能画面から、OpenAIが提供するCodex拡張をインストールします。Codexアイコンが見えない場合は、コマンドパレットから `Codex: Open Codex Sidebar` を実行します。

エディタで開いているファイルや選択範囲を渡しやすいのが利点です。ターミナル操作に慣れていない人はこちらでも構いません。CLIと拡張では画面や利用できる機能が異なることがあるため、「まったく同じ操作」とは考えないでください。

- [Codex IDE拡張の公式ガイド](https://learn.chatgpt.com/docs/codex/ide)

## 4. 最初は読み取り専用で使う

Codex CLIでは、対話中に `/permissions` を実行すると、何を自動で行えるかを変更できます。表示される名前はバージョンや管理設定によって変わる場合があります。

初心者は、最初に次を確認してください。

1. `/permissions` を開く
2. まず `Read Only` を選ぶ
3. `/status` で現在の設定と作業ディレクトリを確認する

`Read Only` は、コードの説明や変更前の相談に向いています。実際に編集させる必要があるときだけ、ブランチを作ったあとで書き込み可能な設定へ変更します。

書き込み可能な設定では、**編集のたびに必ず確認画面が出るとは限りません。** 作業後は `/diff` またはターミナルの `git diff` で、変更を自分の目で全部確認してください。

`--dangerously-bypass-approvals-and-sandbox` のように承認と保護機能を無効化する設定は、このプロジェクトでは使いません。

## 5. AGENTS.mdの扱い

リポジトリのルートにある [`AGENTS.md`](../AGENTS.md) は、CodexなどのAIエージェント向け追加指示です。Codexは作業前にこのファイルを読みます。

ただし、指示はこの1ファイルだけとは限りません。

- `~/.codex/AGENTS.md` など、利用者個人のグローバル指示
- リポジトリルートの `AGENTS.md`
- 作業中のサブディレクトリにある `AGENTS.md` または `AGENTS.override.md`

基本的には、作業場所に近い下位ディレクトリの指示が後から読み込まれ、上位の指示より優先されます。どの指示が有効か疑わしい場合は、Codexに「現在有効な指示ファイルを列挙して」と尋ねて確認します。

人間向けの参加手順は `AGENTS.md` ではなく [`ONBOARDING.md`](../ONBOARDING.md) が正本です。

## 6. 安全な作業手順

Codexを起動する前に、ターミナルでブランチを作ります。以下の `tanaka` は自分の名前やGitHub IDに置き換えてください。

```bash
cd ~/dev/OIF-homepage
git switch develop
git pull --ff-only
git switch -c feat/add-news-tanaka
codex
```

最初の依頼では、対象・変更内容・変えてはいけないもの・確認方法を具体的にします。

```text
lib/news.ts に、担当者から確定済みの告知を1件追加して。
既存の形式に揃え、他のファイルは変更しないで。
まだコミットやpushはしないで。変更後に差分を説明して。
```

作業後はCodexを `/quit` または `/exit` で終了し、人間が確認します。

```bash
git status
git diff
npm run build
npm run dev
```

ブラウザでPC幅とスマホ幅を確認してから、変更したファイルだけをステージします。

```bash
git add lib/news.ts
git diff --cached
git commit -m "feat(news): 9月のLT会告知を追加"
git push -u origin feat/add-news-tanaka
```

コミットとpushまでCodexに任せる必要はありません。最初のうちは、この部分を自分で行うほうが変更の範囲を把握しやすくなります。

## 7. 良い頼み方

1回の依頼を小さくし、対象ファイルと終了条件を書きます。

```text
components/layout/Header.tsx を確認して。
画面幅375pxでロゴとメニューが重なる原因を説明して。
PC表示は変えない前提で修正案を出して。まだ編集しないで。
```

```text
今の git diff をレビューして。
問題があれば重要な順に指摘だけして、ファイルは変更しないで。
```

```text
このエラーの意味を初心者向けに説明して。
原因を確認するためのコマンドは提案してよいが、まだ実行しないで。
```

避ける依頼:

- 「サイトをかっこよくして」のように範囲がない依頼
- 複数の機能を一度に作らせる依頼
- 内容を確認せず「全部直して、コミットして、pushして」と任せる依頼
- APIキー、学籍番号、非公開の議事録などをプロンプトに貼ること

会話が長くなって話が混ざったら、`/new` で新しい会話を始めます。

---

## 8. 最後に必ず守ること

- **AIの差分を読まずにコミットしない**
- **`main` / `develop` に直接コミット・pushしない。** 作業ブランチは `develop` から切り、PRの base も `develop`
- **`git push --force` を使わない**
- デプロイ設定、依存パッケージ、対外文言を勝手に変更させない
- `.env`、APIキー、個人情報をCodexへ渡さない
- わからない変更は破棄するか、Discordで人間に確認する

Codexは学習と作業の補助です。使うかどうかにかかわらず、最終確認とPRの説明は自分で行ってください。
