# デザインについて

> 最終更新: 2026-08-06
>
> **このドキュメントは短くしてあります。それが意図です。**
> デザインは基本的に自由にやってください。ここに書いてあるのは「守ってほしい最低限」と「今こうなっている」の2つだけで、後者は**説明であって規則ではありません**。変えたければ変えて構いません。

---

## 守ってほしいこと（これだけ）

デザインの好みの問題ではなく、守らないとサイトとして壊れるものです。

1. **スマホで壊れないこと。** 訪問者の多くはスマホです。375px幅で確認してください（`F12` → 端末アイコン）
2. **読めること。** 本文と背景のコントラストを十分に取る。極端に小さい文字を使わない
3. **重くしないこと。** 常時動くアニメーション、大量の画像、重いJSライブラリは、スマホの体感速度を殺します。演出を足すときは実機で確認を
4. **文言は変えないこと。** キャッチコピー・団体の説明文・SEOのメタ情報は、見た目の変更のついでに書き換えないでください。OIFの方向性の正本は Notion です。文言を変えたいときは代表に相談してください

**これ以外は自由です。** 色を足す、レイアウトを変える、写真の使い方を変える、全部やっていいです。

## 今はこうなっている（現状の説明）

新しく入った人が「なぜこうなっているのか」を掴むための情報です。**踏襲する義務はありません。**

- **白を土台にした白黒基調。** 文字・線は黒 `#0B0C0E`、ページ背景は白 `#FFFFFF`。彩度のあるアクセント色は今のところ使っていません
- **角丸なし。** `tailwind.config.ts` で、Tailwindの角丸トークンを0にしています
- **境界線で構造を作る。** 面を塗り分けるより、細い線でセクションを仕切る
- **余白を広めに取る。** 1画面に詰め込まない
- **写真は用途を分ける。** トップのキャンパス画像、活動スナップショット、イベントのチラシとして使っています。現在は写真を全セクションの背景にはしていません
- **動きは控えめ。** fade-up、スクロールに応じた表示、マーキー、ページ遷移など。CSSで済むものはJavaScriptを増やさず実装しています
- **書体。** 本文は Inter、ラベルや数値は JetBrains Mono

参考にしてきたのは Vercel、Linear、Stripe あたりの「開発者向けサービスのミニマル」系です。

## 実装するときの場所

見た目をいじるときに触るファイル:

| 何 | どこ |
|---|---|
| 色・書体・余白・イージングの定義 | `tailwind.config.ts` |
| グローバルなスタイル、共通クラス | `app/globals.css` |
| ヘッダー・フッター | `components/layout/` |
| 汎用の部品（ボタン、アニメーション） | `components/ui/` |
| ページ固有のセクション | `components/site/` |
| 画像 | `public/images/` |

**色や余白は、まず既存のTailwindクラスを使ってください。** `p-6` `gap-4` `text-ink` のような標準クラスや既存トークンは、そのまま使えます。`#1a2b3c` や `mt-[37px]` のような生の値を何度も直書きすると、あとで全体を調整できません。サイト全体で繰り返し使う新しい色・余白・動きは、`tailwind.config.ts` のトークンとして定義します。

Tailwind のクラス名の読み方は [`nextjs-guide.md`](./nextjs-guide.md#6-tailwind-css--classname-の読み方) にあります。

## 大きく変えたいとき

サイト全体のトーンを変えたい、配色を変えたい、というレベルの提案は歓迎です。**ただし、いきなり全ページを書き換えたPRを出さないでください。** レビューできないし、戻せません。

進め方の目安:

1. Discord で「こういう方向にしたい」を先に共有する（スクショ・参考サイトのURL・Figma、なんでも）
2. **1ページか1セクションだけ**で試作してPRを出す
3. 良さそうなら、他のページに広げる

小さい調整（1つのセクションの余白、ボタンの見た目、写真の差し替えなど）は、いちいち相談せずPRを出して構いません。

## デザインから入る人へ

コードを書いたことがなくても、このリポジトリでできることはあります。

| やること | 触るファイル | 必要な知識 |
|---|---|---|
| 写真の差し替え・追加 | `public/images/` + 参照元のコンポーネント | ほぼ不要 |
| 余白・文字サイズ・色の調整 | 該当コンポーネントの `className` | Tailwind のクラス名（すぐ覚えられる） |
| セクションの並び替え | 該当ページの `page.tsx` | JSX が読める程度 |
| 新しいセクションを作る | `components/site/` に新規ファイル | React の基礎 |

最初は「既存のコンポーネントをコピーして数値を変える」から始めるのが確実です。環境構築は [`../ONBOARDING.md`](../ONBOARDING.md) を見てください。

Figma などで作ったカンプをそのまま実装してもらう、という進め方も可能です。実装できる人とペアを組みたい場合は Discord で言ってください。

### 環境構築なしで見た目を確認する方法

PRが作られると、Vercel の bot が**プレビューURL**をコメントします。そこを開けば、**手元に開発環境を作らなくても、変更後の見た目をそのまま確認できます。** スマホの実機で開いてチェックするのにも使えます。

「実装は他の人、見た目の判断は自分」という分担をしたい場合、このURLをやりとりするのがいちばん速いです。
